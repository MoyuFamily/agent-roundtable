# 圆桌讨论结论：如何实现多 Agent 圆桌讨论更合理和高效

## 讨论概要
- **参与者**: 饼哥（产品总监）、像素姐（设计总监）、码飞（技术总监）
- **协调者**: 小赫
- **轮次**: 3 轮 + 开场白
- **状态**: concluded

## 共识点 ✅

1. **独立 skill 方向正确** — 讨论和任务是两个概念，不应该混入 kanban
2. **一句话发起是必须的（P0）** — 用户说「帮我召集 XX 讨论 YY」就够了，不需要手动配置参数
3. **MVP 用 delegate_task + roundtable toolset** — 先证明价值，V2 改 event-driven
4. **飞书同步提升到 P1** — Boss 需要看到讨论进展，不能只看最终结论
5. **结论由 coordinator 生成** — 不用 LLM 自动生成，用结构化数据让 coordinator 写，质量更可控
6. **独立 SQLite + WAL 模式** — 读写互不影响，避免 kanban.db 锁冲突

## 分歧点 ⚠️

1. **通信机制优先级**
   - 码飞：P0（不改就无法真正工作）
   - 饼哥/像素姐：MVP 先跑通，V2 再优化
   - **结论**：MVP 用 delegate_task，V2 改 event-driven

2. **发言展示形式**
   - 像素姐：富文本（引用块、高亮共识/分歧）
   - 码飞：纯文本足够
   - **结论**：MVP 纯文本，V2 考虑富文本

3. **打断机制**
   - 像素姐：加「紧急发言」选项
   - 码飞：MVP 不需要
   - **结论**：放到 V2
