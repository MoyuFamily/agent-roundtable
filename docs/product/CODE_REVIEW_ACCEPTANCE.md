# Code Review 验收：Windows 可用性

日期：2026-11-17。评审快照：ce959f09e92080bb659f66eac9c30e1bd5ce2675。

## 结论

本次证明了 Roundtable 能承载真实代码审阅、保存独立意见及交叉回应，并追溯到原始发言。它没有证明多角色比单助手更有效：单助手基线找到了三个角色共同发现的四类功能缺陷，还额外找到了撤销链接覆盖并发更新的问题。多角色主要补充了测试设计细节与证据边界，重复意见较多。

工程修复的有效性以实际回归为准，而非评审者投票。Windows 与 Linux 完整源码检查、实际 Chrome 导出和 MCP 双客户端检查已通过；干净 wheel 验证在 Ubuntu 通过。

## 材料与执行方式

- 问题：当前 Viewer 与 Agent 传输能否视为 Windows 可用？检查快照更新、并发、Unicode、PDF 取消及真实入口。
- 一个独立 Agent 作完整审阅基线；三个独立 Agent 分别负责正确性、可靠性、维护性。首轮只接收同一冻结代码、共同简报和各自角色提示词。
- 基线不进入多角色会议。三个角色第二轮读取彼此完整发言及 Roundtable 回应提示词；角色始终不读取基线、后续修复或实时工作树。
- 会议 ID 为 rt_fa46267d。宿主经真实 HTTP /tool 获取提示词、保存发言和结论；模型执行、文件访问及证据核对由宿主负责。
- 首次并发尝试因429、连接中断及服务过载未产生报告；失败不算作有效分析。后续以较低并发完成。会议数据库跨中断保留，恢复时只有开场，未填造角色发言。
- Agent 使用继承配置，未指定不同模型。没有独立的 token、费用及等预算控制；不构成异模型比较。

## 首轮结果与验证

| 根因 | 单助手 | 正确性 | 可靠性 | 维护性 | 维护者处理与证据 |
|---|---|---|---|---|---|
| Windows 不能用原有 rename 覆盖快照 | BL-001 | COR-001 | REL-001 | MAI-001 | 共享 os.replace 写入；Windows 连续更新回归通过。原实现平台语义为静态判断，受控探针验证失败后的应用行为 |
| 缺少 fcntl 时锁退化为空操作 | BL-002 | COR-002 | REL-002 | MAI-002 | 共享平台锁；独立进程快照与 JSONL 并发回归通过。旧实现丢更新由受控交错探针复现 |
| 隐式文本编码损坏 Unicode | BL-003 | COR-003 | REL-004 | MAI-003 | 文件边界明确 UTF-8；旧实现以 CP1252 替身复现，新实现验证中文及 emoji。未覆盖所有 Windows 地区设置 |
| PDF 取消未拥有 Windows 浏览器进程树 | BL-004 | — | REL-003 | MAI-004 | taskkill 结束本请求树；启动真实 Chrome 后取消并检查进程。Windows 暴露 EBUSY，采用有界异步目录清理后通过 |
| Node 撤销与 Python 快照更新竞争 | BL-005 | — | — | — | 撤销改为独立哈希标记；验证不改写快照，后续旧快照写入不能恢复访问 |
| PDF 清理测试未证明浏览器已启动或退出 | BL-004 注释 | — | REL-005 | MAI-004 注释 | 设置真实临时根目录、等待浏览器就绪、检查残留进程；这是验证缺陷，不重复计为新的功能缺陷 |

三个角色共提出12条编号发现，按根因合并后为四类功能缺陷和一类测试设计缺陷。单助手报告五类功能缺陷，并已提到取消测试的局限。所有报告均区分 macOS 受控探针、静态平台推断和真实 Windows 运行，不把模拟当成实机证据。

维护过程中另外发现：将浏览器 TMPDIR 嵌入深层评审目录会触发 Linux Unix socket 路径上限；Windows 浏览器退出后，文件句柄短暂未释放会产生 EBUSY。这两项来自运行修复分支的 CI，不记为冻结快照中任何 Agent 的发现。

## 交互价值与边界

回应阶段将重复发现合并为共同根因，正确性角色补入了其他角色指出的 PDF 所有权问题，并澄清“模拟文件替换失败”不等于“在 Windows 上执行过”。这提升了证据描述的一致性，但个人角色补齐盲点不等于整个团队新增发现。

本案例没有等时间或等 token 预算，没有盲评，维护者同时是实现作者及最终核验者；缺陷全集未知，不能据此计算漏报率或宣称准确率。单案例也不能推断七类产品场景的总体收益。较长原始发言需要宿主额外提供完整材料，摘要与提示词摘录不能代替证据核对。

当前取舍：继续维护已验证的记录与协作能力，但不因本案例扩大自动角色选择或模型路由。后续选实际需求变化或存在不同专业约束的评审，在相近预算下对比单助手、独立角色汇总及交互阶段；只有重复出现的增益才支持增加编排复杂度。用户其余重要决策场景仍保留。
