让专业视角共同参与决策

Roundtable 的目标是为重要决策和 Code Review 组织合适的专业角色，让不同 Agent 与模型承担分析，帮助你比较方案、理解代价并作出取舍。

角色定义职责，Agent 提供上下文与工具，模型承担分析。当前由你或协调者组织评审，自动组队与模型路由仍待实现。

一个选择，往往涉及多个专业

产品价值、实现成本、使用体验和持续运营会彼此影响。评审需要覆盖这些视角，并把冲突变成可比较的选择。

PAIN 01

缺席的专业视角

为问题选择角色，明确各自必须回答的问题、需要的资料和交付物，检查重要职责是否遗漏。

角色覆盖 · 具体职责
PAIN 02

分析缺少专业深度

各角色给出具体方案、证据和约束，并说明缺少的信息及会改变判断的条件。

专业贡献 · 可查依据
PAIN 03

意见齐全，仍难取舍

协调者比较方案收益、成本与适用条件，保留反对意见，向用户交付有理由的建议。

方案比较 · 保留分歧

当前可用的评审基础

已有记录、轮次、展示与提示词能力。宿主负责运行 Agent 和选择模型，协调者负责语义综合；创建会议不会自动启动模型。

01

Define Responsibilities

用 context 记录决策简报，用角色 perspective 记录专业问题和交付物。

02

Record Contributions

按角色记录分析与引用，先各自判断，再回应影响选择的冲突。

03

Retain Evidence

保留原始发言与资料引用。已有共识标注比例不代表结论正确率。

04

Compare Options

协调者从记录形成方案比较、代价与待验证问题，并记录建议。

从专业分析到用户取舍

以问题覆盖、信息增益和预算控制讨论，允许保留分歧和暂缓决定。

明确问题与角色

brief + responsibilities

各自专业分析

evidence + options

回应重要冲突

constraints + alternatives

交付取舍依据

recommendation + dissent

Source and integration

从现有 Agent 工作流开始

下面演示创建会议记录。新版评审提示词与模板位于 GitHub 源码，请核对发布包能力；宿主需提供真实 Agent 分析。核心使用 SQLite，Web Viewer 启动失败可降级。

Package: agent-roundtableImport: roundtableNode.js 18+ for Web Viewer
quickstart.py
pip install agent-roundtable

from roundtable import RoundtableCore

core = RoundtableCore()
result = core.create_discussion(
    topic="选择数据库：PostgreSQL vs MySQL vs TiDB",
    participants=[
        {"profile": "architect", "role": "架构师"},
        {"profile": "ops", "role": "运维工程师"},
        {"profile": "product", "role": "产品经理"},
    ],
    max_rounds=3,
)
print(result["web_status"], result.get("web_url"))

决策与评审场景

七类场景共用专业评审流程，按问题调整角色、资料和交付物。Code Review 与其他场景并列；当前提供通用流程和部分专用模板，效果需在真实任务中验证。

USE

项目去留与方向

比较继续、调整或停止的价值与成本，明确投入边界、验证计划和复审条件。

USE

产品范围与优先级

比较目标用户、MVP 范围和优先级，明确收益、代价、暂缓项与验收方式。

USE

技术路线

比较自研、采购、架构与迁移方案，明确依赖、维护成本和退出路径。

USE

发布与实施

评估上线条件、阻塞项、实施步骤、回滚条件和未验证部分。

USE

资源与商业模式

比较预算与人力分配、免费或收费方案，明确成本、需求假设和试点指标。

USE

工作流程与工具选择

结合实际使用者和现有流程，比较工具收益、迁移、培训、维护和退出成本。

USE

Code Review

检查实际改动与上下文，交付带代码定位和证据的问题清单、阻塞项与合并建议。
